# 重点主题帖子挖掘规则

## 目的

用于判断重点主题下监控账号发布的帖子是否值得形成 Hot Event 或运营机会。

本规则面向 `x_post` Signal。重点主题页面展示的是帖子榜单，不再把多个帖子强行聚合成“话题候选”。只有当证据显示多个帖子确实指向同一个具体事件时，Agent 才可以把它们作为同一事件的证据链。

## 输入对象

每条 `x_post` Signal 至少应关注：

- 帖子正文、链接、发布时间、首次采集时间和最近采集时间。
- 作者账号、账号所属主题圈、账号角色、来源角色、单点权限和权威范围。
- 公开互动指标，例如浏览、点赞、回复、转发、引用。
- 是否存在历史快照、作者近期表现基线或跨账号重复讨论。

## 成立事件的基本要求

形成 Hot Event 前必须同时满足：

- 能识别清楚的主体、动作、对象和时间。
- 事件不是泛泛观点、情绪表达或无事实的新梗。
- 至少有一条可打开的真实来源链接。
- 能说明为什么现在值得运营关注。
- 与已有 Hot Event 不重复；如果是同一事件的新证据，应更新已有事件上下文。

## 优先触发路径

以下路径命中时，倾向形成 Hot Event。路径命中不是自动编造事件，仍需结合正文和证据判断。

### TW-01：第一方权威账号发布重大事实

当 S1 第一方权威账号在其权威范围内发布重大事实时，倾向形成事件。

示例：

- 官方账号发布产品、政策、合作、结算、安全、监管或经营变化。
- 官方账号澄清争议、确认故障、宣布结果或撤回原计划。

需要输出的触发原因：

- “第一方权威账号在其权威范围内发布了可核验的重大事实。”

### TW-02：核心行业账号发布明确行动或判断

当 S2 核心行业账号发布明确行动、重要判断、可信爆料或行业变化线索时，倾向形成事件。

示例：

- 行业账号披露交易、监管、融资、合作、产品变化或市场结构变化。
- 高影响力账号对一个正在发生的行业问题给出具体判断，并带有可追溯依据。

需要输出的触发原因：

- “核心行业账号发布了明确行动或判断，且帖子包含可引用依据。”

### TW-03：单条帖子流量异常

当单条帖子公开互动显著高于该账号近期表现时，倾向形成事件。

优先使用：

- 作者近期表现前 5%。
- `Tmax >= 3`。
- 账号历史基线或多时点快照。

如果缺少账号基线，不要假装已经验证，应在 `missingData` 中说明“缺少账号近期表现基线”。

需要输出的触发原因：

- “该帖子公开互动显著高于账号近期基线，出现单点流量爆发。”

### TW-04：圈内帖子榜单靠前

当帖子进入所属主题圈榜单前 3，且内容具备清晰事件事实或运营角度时，倾向形成事件。

需要输出的触发原因：

- “该帖子进入重点主题圈内帖子榜单前 3，且内容指向清晰事件。”

### TW-05：全局主题榜单靠前

当帖子进入全部主题圈综合榜单前 10，且内容具备清晰事件事实或运营角度时，倾向形成事件。

需要输出的触发原因：

- “该帖子进入重点主题综合榜单前 10，具备跨主题关注价值。”

### TW-06：多账号指向同一具体事件

当多个监控账号在短窗口内讨论同一具体事件，且主体、动作、对象和时间一致时，倾向形成同一个 Hot Event。

注意：

- 相同关键词不等于同一事件。
- 相似行业方向不等于同一事件。
- 如果只是多个账号讨论同一大类主题，但具体事实不同，应保留为多个帖子信号，不要合并。

需要输出的触发原因：

- “多个监控账号在短窗口内指向同一具体事件。”

## 应忽略的情况

以下情况不应形成 Hot Event：

- 帖子只有情绪、段子、普通转述或泛泛观点。
- 只出现同一关键词，但具体事件不一致。
- 链接不可打开，且没有其他可核验证据。
- 帖子只是重复历史信息，没有新的事实、窗口或运营价值。
- 指标看起来高，但来源不可信或缺少正文上下文。

## 输出要求

Agent 输出必须使用中文。

如果形成事件：

- 标题必须是事件概要，不要直接使用帖子原文。
- 摘要必须说明“发生了什么”和“为什么值得关注”。
- `triggerReason` 必须说明具体命中了哪条触发路径。
- `evidenceRefs` 必须指向真实帖子或补充证据。
- 标签只表达来源和热度属性，例如 `Topic Circle`、`第一方确认`、`Re-entry`，不要把标签当作触发原因。

如果不形成事件：

- 说明缺少什么事实或证据。
- 不要因为账号重要就强行形成事件。
