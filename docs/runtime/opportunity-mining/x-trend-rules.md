# X 热搜挖掘规则

## 目的

用于判断 X / Twitter 热搜 Signal 是否值得形成运营机会或事件。

## 关注对象

- 热搜词本身。
- 热搜出现的地区和时间。
- 排名变化、跨地区上榜、持续时间。
- 相关讨论是否指向明确事件。
- 是否能找到可靠事实依据。

## 判断倾向

以下任一规则命中，即倾向形成事件响应。规则命中后仍需要检查事实依据和重复事件，不允许只凭热搜词条编造事件。

## 事件响应规则

### TR-01：首次进入头部榜单

具体 Event 首次进入任一输入榜单第 1-5 位时，倾向形成事件响应。

需要证据：

- 当前 Signal 或 Evidence 中的地区、排名、观察时间。
- 如可用，调用 `xTrend.getRecentDiffs` 检查该 query 是否为新进榜或首次进入头部区间。

输出倾向：

- 如果热搜词背后能确认具体事件，输出 `create_event` 或 `create_opportunity`。
- 如果只有热搜词，没有明确事实，输出 `request_human_review`。

### TR-02：相邻快照排名显著上升

同一具体 Event 在相邻两次成功快照间上升至少 10 位时，倾向形成事件响应。

需要证据：

- 调用 `xTrend.getRecentDiffs` 查询同一 query 的最近 diff。
- 重点查看 `previousRank`、`currentRank`、`rankDelta`、`diffType`。
- `rankDelta >= 10` 表示排名显著上升。

输出倾向：

- 如果上升背后能找到明确原因，倾向形成机会或事件。
- 如果排名上升但缺少原因，输出 `request_human_review` 并写明缺少热搜原因证据。

### TR-03：命中重点主题

具体 Event 语义命中已配置重点主题时，倾向形成事件响应。

需要证据：

- 调用 `topicWatch.listActive` 获取当前启用的重点主题。
- 将热搜 query、标题、摘要、相关证据与重点主题的名称、描述、监控意图、触发策略进行语义匹配。
- 如果只是字面相似但语义不一致，应写入风险说明。

输出倾向：

- 命中重点主题且有事实依据时，倾向形成机会。
- 命中不确定时，输出 `request_human_review`。

### TR-04：多地区同时上榜

同一具体 Event 同时出现在至少两个输入地区榜单时，倾向形成事件响应。

需要证据：

- 调用 `xTrend.getCrossRegionPresence` 查询同一 query 在近期窗口内出现过的地区。
- `regionCount >= 2` 可作为多地区上榜证据。
- 需要保留各地区排名和观察时间，避免把不同时间段的零散出现误判为同时热议。

输出倾向：

- 多地区上榜且语义指向同一事件时，倾向形成事件或机会。
- 多地区出现但含义可能不同，应请求人工复核。

## 通用判断倾向

倾向形成机会或事件：

- 热搜背后有明确新闻事件、产品发布、争议、行业变化或公共议题。
- 多地区同时讨论，且不是纯娱乐噪音。
- 排名上升或持续在榜，说明讨论窗口仍然存在。
- 可以和产品、行业观点或用户痛点建立合理连接。

倾向忽略：

- 只有词条热度，没有明确事实。
- 明显是纯粉圈、抽奖、无上下文玩梗。
- 与目标产品或账号定位没有可解释的连接。
- 缺少任何可引用证据。

## 需要证据

- 至少一条解释热搜原因的证据。
- 如果要形成事件，应能说明事件主体、动作、时间和影响。
- 创建事件或机会前，应调用 `event.findSimilar` 或 `opportunity.findSimilar` 检查是否已经存在相似结果。
- 如果证据不足，应请求人工复核或继续观察。
