# 任务分发 Agent 架构设计（已废弃）

本文件保留用于说明历史方案已经废弃。

新系统不再设计独立的“任务分发层”，也不再把 Event 自动拆成一组账号任务。热点形成后，运营入口统一收口到 Event 详情里的“热点运营”工作区。

## 当前方向

新的业务链路是：

```text
Event / Opportunity
→ 热点运营工作区
→ 查看事实依据和风险
→ 查看可用运营账号
→ 选择账号、承接角度和内容要求
→ 生成候选内容
→ 人工发布并回填链接
→ 效果追踪
```

系统可以使用 Agent 辅助推荐账号、承接角度和内容要求，但它只是热点运营工作区里的辅助能力，不再作为独立的任务分发 Agent 存在。

## 为什么废弃任务分发层

任务分发层容易把系统变成下游任务派发工具，而不是围绕热点本身提供分析、承接和内容运营能力。

当前设计强调：

- 入口围绕热点，而不是围绕任务列表。
- 运营先看 Event 的事实依据、风险和机会判断。
- 账号、内容要求、候选生成、发布回填都在同一个热点上下文里完成。
- 内容生成接收的是热点运营上下文，不是任务分发结果。
